## Что мы делаем и зачем?

**Задача:** обнаружить аномальный (вредоносный) сетевой трафик без использования меток классов — то есть **unsupervised anomaly detection**.

В реальной жизни таких задач много: антивирусы, антифрод в банках, мониторинг серверов. У нас обычно нет полной разметки — атаки бывают новыми, никто их раньше не видел. Нужен метод, который сам найдёт "что-то странное" в данных.

**Идея:** нормальный трафик образует плотные группы похожих между собой запросов. Атаки — это редкие, нетипичные точки в стороне от этих групп. Достаточно найти эти "одиночные" точки.

**Пайплайн:**

```
Сырые данные (25192 × 42)
      ↓ Preprocessing
Кодирование категорий + StandardScaler (25192 × 41)
      ↓ PCA
Сжатие до 2D (25192 × 2)
      ↓ HDBSCAN / KMeans
Кластеры + метки аномалий
      ↓ Визуализация
Scatter plot с цветными кластерами
```

## Шаг 1 — Preprocessing

### Кодирование категориальных признаков

Алгоритмы машинного обучения работают только с числами. Строки типа `"tcp"`, `"http"` нужно превратить в числа.

```python
for col in categorical_cols:
    encoder = LabelEncoder()
    X[col] = encoder.fit_transform(X[col])
```

`LabelEncoder` присваивает каждой уникальной строке целое число: `tcp` → 0, `udp` → 1, `icmp` → 2.

**Важный нюанс:** Label Encoding вводит ложный порядок (`icmp > udp > tcp`). В строгом смысле для категорий без порядка лучше One-Hot Encoding. Но здесь это допустимо — нас интересует общая структура данных, а PCA всё равно будет линейно комбинировать признаки.

### Стандартизация (StandardScaler)

```python
scaler = StandardScaler()
X_scaled = scaler.fit_transform(X)
```

Для каждого признака:

$$x_{\text{new}} = \frac{x - \mu}{\sigma}$$

После этого все признаки имеют **среднее = 0, стандартное отклонение = 1**.

**Почему обязательно:** в данных есть `src_bytes` (миллионы) и `serror_rate` (0–1). Без масштабирования PCA увидел бы только разброс `src_bytes` и проигнорировал всё остальное (см. Q2).

## Шаг 2 — PCA (Principal Component Analysis)

### Идея PCA

PCA — это метод **снижения размерности**. Он находит новые оси координат, вдоль которых данные разбросаны максимально.

**Пример из жизни:** представь облако точек в форме эллипса в 3D. Главная компонента — это длинная ось эллипса (направление максимального разброса). Вторая — поперечная ось. Третья — самая короткая (можно отбросить).

В наших данных 41 признак → 41 ось. PCA находит 2 главных направления и проецирует данные на плоскость.

### Математика (коротко)

1. Вычисляется ковариационная матрица $C = \frac{1}{n}X^T X$ (для уже центрированных данных)
2. Находятся её собственные векторы и собственные значения
3. Собственные векторы — это **главные компоненты** (новые оси)
4. Собственные значения — это **дисперсия** вдоль каждой оси

Берём 2 вектора с наибольшими собственными значениями → они объясняют максимум дисперсии.

### Что такое explained_variance_ratio_?

```python
print(pca.explained_variance_ratio_)
# [0.19786294 0.13288356]
```

Это доля дисперсии исходных данных, которую сохраняет каждая компонента:

- **PC1: 19.8%** — первая компонента передаёт ~1/5 всей информации
- **PC2: 13.3%** — вторая компонента ~1/8
- **Total: 33%** — две компоненты сохраняют треть исходной дисперсии

Звучит мало, но это нормально для 41-мерного датасета: мы сжимаем 41 признак в 2, и треть дисперсии — это много. Главное — что главные направления разброса (а значит и кластеры/выбросы) сохраняются.

### Почему нельзя без нормализации?

Дисперсия зависит от единиц измерения. `src_bytes` имеет дисперсию в миллиарды раз большую, чем `serror_rate`. PCA бы решил что PC1 = `src_bytes`, PC2 = `dst_bytes`, и вся информация из 39 других признаков просто пропала бы.

После `StandardScaler` все признаки равноправны — PCA честно ищет реальные направления разброса.

## Шаг 3 — HDBSCAN (Hierarchical Density-Based Spatial Clustering)

### Идея

HDBSCAN ищет **области высокой плотности точек**. Места где точки расположены кучно — это кластеры. Одиночные точки в "разреженных" областях — это шум/аномалии.

**Пример из жизни:** карта города. Жилые районы — плотные кластеры зданий. Одинокий дом в лесу — выброс.

### Параметры

```python
hdbscan.HDBSCAN(min_cluster_size=50, min_samples=10)
```

- `min_cluster_size=50` — минимальный размер кластера. Группы меньше 50 точек НЕ считаются кластером (они становятся шумом)
- `min_samples=10` — насколько "плотным" должен быть кластер. Чем больше — тем строже требование к плотности, тем больше точек будет помечено как шум

### Метка -1

```python
np.unique(cluster_labels)
# array([-1,  0,  1, ...])
```

- `0, 1, 2, ...` — индексы кластеров
- **`-1` — это аномалии/шум.** Точки, не попавшие ни в один плотный кластер.

Это именно то, что нам нужно: метка `-1` = подозрительный трафик.

### Преимущества HDBSCAN

1. **Не нужно задавать число кластеров** — сам определит
2. **Произвольная форма кластеров** (не только сферы как у KMeans)
3. **Автоматически выделяет шум** — идеально для anomaly detection
4. **Иерархия плотностей** — может работать с кластерами разной плотности

### Почему PCA перед HDBSCAN?

В 41-мерном пространстве работают два злых эффекта:

1. **Проклятие размерности:** в высокой размерности все точки оказываются примерно одинаково далеко друг от друга. Понятие "плотность" разрушается.
2. **Скорость:** HDBSCAN строит mutual reachability graph и иерархию — для 25192 точек × 41 признак это медленно.

PCA до 2D решает обе проблемы.

## Шаг 4 — KMeans (для сравнения)

### Идея

KMeans разбивает точки на $k$ кластеров. Каждый кластер задаётся **центроидом** — средней точкой кластера.

**Алгоритм (упрощённо):**
1. Случайно выбираем k центроидов
2. Каждую точку приписываем к ближайшему центроиду
3. Пересчитываем центроиды как среднее точек кластера
4. Повторяем 2-3 пока центроиды не перестанут двигаться

### Параметры

```python
KMeans(n_clusters=2, random_state=42, n_init=10)
```

- `n_clusters=2` — задали 2 кластера заранее (нормальный/аномальный)
- `random_state=42` — для воспроизводимости (одинаковый запуск → одинаковый результат)
- `n_init=10` — запустить с 10 разных стартовых положений центроидов и взять лучшее. Защищает от плохой случайной инициализации.

### Почему KMeans плохо подходит для anomaly detection

| Проблема | Объяснение |
|----------|------------|
| Все точки попадают в кластер | KMeans не знает понятия "выброс". Каждая аномалия попадёт в ближайший кластер и затеряется в нём |
| Сферические кластеры | KMeans делит плоскость прямыми линиями (диаграмма Вороного). Если данные сложной формы — он плохо их разделит |
| Чувствителен к выбросам | Аномальная точка тянет центроид на себя, искажая границу |
| Нужно знать k | На практике мы не знаем сколько типов атак есть |

---

## Сравнение HDBSCAN vs KMeans

| Критерий | HDBSCAN | KMeans |
|----------|---------|--------|
| Число кластеров | Само определяется | Нужно задать `n_clusters` |
| Форма кластеров | Любая | Только сферическая |
| Аномалии | Метка `-1` | Нет понятия аномалии |
| Кластеры разной плотности | Да | Нет |
| Чувствительность к выбросам | Низкая | Высокая |
| Скорость | Медленнее | Быстрее |
| Подходит для anomaly detection | **Да** | **Нет** |

## Разбор Question 1–5

### Q1 — Что значат explained variance ratio?

Доля исходной дисперсии, сохранённая каждой компонентой:
- PC1 ≈ 19.8% дисперсии
- PC2 ≈ 13.3% дисперсии
- Total ≈ 33% — две компоненты сохраняют треть информации при сжатии 41 → 2.

### Q2 — Почему нормализуем перед PCA?

PCA опирается на дисперсию. Без нормализации признаки с большими значениями (`src_bytes`) доминируют над rate-признаками (0–1). После `StandardScaler` все признаки равноправны.

### Q3 — Почему PCA перед HDBSCAN?

В высокой размерности расстояния "выравниваются" → плотность теряет смысл (curse of dimensionality). PCA до 2D возвращает осмысленность и сильно ускоряет вычисление.

### Q4 — Как HDBSCAN справился?

**Технически отработал, но качество среднее.** Реальные числа на нашем датасете:

- Нашёл **39 кластеров** + помечил **8 019 точек как `-1`** (≈31.8% выборки).
- Из этих 8 019 "аномалий" реально аномальны только **1 842** → **precision ≈ 23%**.
- Recall на реальных аномалиях: 1842/11743 ≈ **15.7%** — большинство атак НЕ попало в `-1`.

Причина слабого результата: PCA сохраняет всего 33% дисперсии, в 2D-проекции нормальный и аномальный трафик частично смешиваются. Концептуально подход правильный, но проекция оказалась слишком грубой.

### Q5 — HDBSCAN или KMeans?

**На этом датасете KMeans сработал значительно лучше.** Реальные числа:

KMeans на `X_scaled` (41 признак):

| Кластер | anomaly | normal | Precision |
|---|---|---|---|
| 0 (≈ normal) | 2272 | 13327 | 85.4% |
| 1 (≈ anomaly) | **9471** | 122 | **98.7%** |

KMeans-кластер 1 идентифицировал атаки с precision **98.7%** и recall **80.6%**. HDBSCAN на PCA — precision 23%, recall 16%.

**Почему KMeans победил:**
1. Использует все 41 признак, а не сжатую 2D-проекцию.
2. Структура данных бимодальная — две компактные группы — что подходит под сферическое допущение KMeans.
3. Не дробит данные на много мелких кластеров.

**В чём HDBSCAN остаётся теоретически лучше:** не требует задавать `n_clusters`, явно выделяет шум как `-1`, работает с произвольной формой кластеров. Но эти преимущества не помогли, когда PCA срезал критическую информацию.

**Главный урок:** теоретическая пригодность алгоритма ≠ практическая. Всегда проверяй эмпирически.
